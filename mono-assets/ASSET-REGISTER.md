## Filename notes

The current source filenames are intentionally preserved, including:
- `miarana mobile 2.png` (original typo retained)
- `mirana -cover.png` (space before hyphen retained)
- `veblen 2 .png` (space before extension retained)

The manifest references exact paths, so these names work without renaming. If a file is renamed later, update its path in `manifest.json` in the same commit.

## Image integrity and loading

- The original files in `mono-assets/` are used directly.
- No source image is cropped, resized, recompressed, or converted by this integration.
- Project cards use `object-fit: contain` so the complete image and its aspect ratio remain visible.
- Project galleries use the same original files and preserve the full image inside the viewing stage.
- Gallery thumbnails are generated by the browser from the original files; no extra thumbnail files are created.
- The project cover is loaded lazily with browser decoding. Gallery images are requested when the corresponding project is opened.

## Editing order or changing a cover

Edit `manifest.json`:
- Change `cover` to select another existing image.
- Reorder the `gallery` array to change the gallery order.
- Add or remove only paths that exist inside `mono-assets/`.
- Keep each image under the correct project ID.

No source image needs to be renamed to reorder a gallery.
